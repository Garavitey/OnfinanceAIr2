# AGENTS.md

Instructions for coding agents working in this repository. Humans: start with
[`README.md`](README.md) for status and [`HLD.md`](HLD.md) for design rationale.

## What this is

A chat platform that turns a prose system description into rendered UML
diagrams. One prompt in, a stream of validated diagrams out, with version
history and feedback captured as RL training data.

FastAPI backend, single-file vanilla-JS frontend, SQLite locally and Postgres in
the documented production path. Diagram DSL is generated by Claude, then passed
through a real parser before it ever reaches the browser.

## Setup

Nothing in this repo runs on a fresh clone until you do this. Every artefact
below is gitignored, so new clones and new worktrees always start without them:

```bash
/opt/homebrew/bin/python3.13 -m venv .venv     # system python is 3.9: StrEnum fails
.venv/bin/pip install -r requirements.txt
cd validator && npm install && cd ..           # Mermaid parse sidecar (jsdom + mermaid)
mkdir -p vendor && curl -sL -o vendor/plantuml.jar \
  https://github.com/plantuml/plantuml/releases/download/v1.2026.0/plantuml-1.2026.0.jar
cp .env.example .env                           # SQLite + MOCK_LLM=1
.venv/bin/python scripts/init_db.py            # creates the 7 tables in uml.db
```

Smoke test the whole bootstrap in one command — it exercises the venv, both
validators and the jar:

```bash
.venv/bin/python -m app.generate
```

Then `.venv/bin/uvicorn app.main:app` and open the printed URL.

**Use `.venv/bin/python` for every command, never bare `python`/`python3`.** The
system interpreter is 3.9 and fails on `StrEnum` and modern typing syntax.

The PlantUML jar needs Java and Graphviz on PATH (`java -version`, `dot -V`).

## Project facts

- Python 3.13 locally (3.12 is the documented target), FastAPI, SQLAlchemy 2.x,
  the `anthropic` SDK, async throughout.
- LLM is `claude-opus-5`. Always `thinking={"type": "adaptive"}`. Use
  `output_config={"format": {...}}` for JSON-shaped output. Never pass
  `budget_tokens` or `temperature` — both return 400 on this model.
- The frontend is **one file**: `static/index.html`. Vanilla JS, mermaid.js from
  CDN. No npm, no build step, no React.
- The only Node dependency is the Mermaid-parse sidecar at
  `validator/validate.mjs`. Nothing else uses Node.
- `docker-compose.yml` (Postgres + Redis + Kroki) is the documented production
  path and is deliberately **not** the local path. Nothing here runs it.

## Conventions

1. **`app/contracts.py` is frozen.** It is the shared interface every module
   imports. Read it, import from it, do not edit it. If it is genuinely wrong,
   stop and say so rather than patching around it.
2. **Scope your change to what you were asked to do.** If another file needs
   changing, say so in your final message instead of changing it silently.
3. **Match the surrounding code** — same imports, naming, and error style as the
   files next to the one you are editing.
4. **Write portable SQLAlchemy** that runs on both SQLite and Postgres:
   `sqlalchemy.Uuid` (not the Postgres-only `UUID`), `sqlalchemy.JSON` (not
   `JSONB`), `DateTime(timezone=True)` with `server_default=func.now()`.
5. **Redis is optional, always.** `REDIS_URL` unset or unreachable must fall
   back to a process-local dict. Every Redis error path is a cache miss, never
   an exception that reaches a handler.
6. **Mock mode is a first-class code path, not a test fixture.** There is no
   `ANTHROPIC_API_KEY` on this machine, so `MOCK_LLM=1` is the default and the
   only locally runnable mode. Anything you add has to work under it, and any
   canned DSL you add to `app/mock_llm.py` must genuinely pass the validators.

## Rendering and validation

Every generated diagram passes a real parser before the UI sees it. Mermaid goes
through the Node sidecar; PlantUML shells out to the jar with this exact
invocation:

```bash
java -jar vendor/plantuml.jar -tsvg -pipe -failfast2
```

- stdin is the source, stdout is the SVG.
- **exit 0 → valid**; stdout is the finished SVG, use it directly.
- **non-zero → syntax error**; stderr holds `ERROR`, a line number, then the
  message. Join the last two lines into `parse_error`. Do not treat stderr
  content alone as failure — a successful render can still print Java warnings.

`KROKI_URL` is unset by default and is opt-in only: setting it sends diagram
source to a third-party service.

## Verifying

Run something real before reporting work done, and never report an unverified
change as working. If a check genuinely cannot run here — it needs a live API
key, or Docker — run the closest thing that does work, then state plainly which
command you ran and which you skipped and why.

There is no test suite yet. Until there is, "verified" means you executed the
code path and can quote the output.
